How to lower the cost of scheduled AI agent runs

An agent on a cron schedule is cheap per run and expensive per month. The bill is roughly runs × (input tokens + output tokens) × price, and every one of those factors has a lever. This guide lists them in the order that usually saves the most.

1. Run less often (and only when there is work)

Most cron agents run on a fixed interval out of habit. Ask what the job reacts to. A daily digest needs one run. An inbox watcher can be triggered by a cheap script that checks for new items first and only starts the agent when something changed. A pre-check in shell costs nothing in tokens.

2. Shrink the context every run loads

Each run usually re-reads a system prompt, tool schemas, memory files and the task file. That is the input-token line on your bill.

  • Keep long-lived files (strategy, lessons, logs) append-only and load only the tail or a summary.
  • Disable tools the job never uses; tool schemas count as input on every turn.
  • Rotate run logs per day instead of one growing file.

3. Put stable content first so prompt caching works

Providers that support prompt caching bill repeated prefixes at a fraction of the normal input price. Caching only hits when the beginning of the prompt is byte-identical across runs. So: fixed instructions and tool definitions first, then today's date, timestamps and fresh data at the end. A timestamp in line one of the system prompt can silently disable caching for everything after it.

4. Cap the output

Output tokens usually cost several times more than input. Ask for a fixed format ("1–3 lines for the log", a JSON object, a checklist) and keep long reasoning out of the final answer. Write big artifacts to files with tools instead of echoing them back into the conversation.

5. Let quiet runs stay quiet

If nothing changed, the best run ends after one cheap check with a sentinel like [SILENT] and no report. Also stop runaway loops: set a max number of tool calls or turns per run, and a hard timeout.

6. Use the smaller model for routine slices

Triage, formatting and status checks rarely need the top model. Route them to a smaller one and keep the expensive model for planning and code. Subscription-based CLIs (flat monthly fee) can be cheaper than per-token APIs for heavy schedules — compare with the calculator before switching.

7. Measure before and after

Log input/output tokens per run for a week, plug the averages into the calculator, change one lever, measure again. Guessing is how cron bills grow.
